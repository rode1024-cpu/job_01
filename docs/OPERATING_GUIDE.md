# 구직 알림봇 · MD 공고 체크 운영 가이드

이 문서는 지금까지 이 프로젝트를 어떻게 만들고 고쳐 왔는지, 새 컴퓨터에서 어떻게 이어서 하면 되는지를 정리한 거예요.
컴퓨터를 포맷해도 이 문서와 코드는 GitHub 저장소(`rode1024-cpu/job_01`)에 남아 있어요.

## 0. 먼저 읽을 것 (컴퓨터 해킹 대응)

결론부터 말하면, 알림봇은 GitHub 서버에서 돌아가서 내 컴퓨터가 없어도 계속 돌아요. 다만 해킹된 컴퓨터에서 로그인하거나 입력했던 정보는 다 바꾸는 게 안전해요.
무엇이 유출됐는지는 저도 확인할 수 없어서, 아래는 "의심하고 바꾸는" 순서예요. 포맷하기 전에 깨끗한 다른 기기(폰 등)에서 먼저 하는 걸 권해요.

1. GitHub
   - 비밀번호 변경, 2단계 인증(2FA) 켜기
   - Settings → Sessions에서 모르는 로그인 세션 종료 [메뉴 이름은 바뀔 수 있어요, 검증 필요]
   - Settings → SSH and GPG keys, Developer settings → Personal access tokens에서 모르는 항목 삭제
   - 저장소의 Actions 탭과 커밋 기록에서 내가 하지 않은 변경이 없는지 확인
2. 텔레그램 봇 토큰 (`TELEGRAM_TOKEN`)
   - 텔레그램에서 @BotFather → `/mybots` → 내 봇 → API Token → Revoke current token으로 토큰을 새로 받기
   - 새 토큰을 GitHub 저장소 Settings → Secrets and variables → Actions의 `TELEGRAM_TOKEN`에 다시 저장
   - 텔레그램 앱의 "연결된 기기"에서 모르는 기기 로그아웃
3. 사람인 API
   - 사람인 계정과 사람인 API 사이트 비밀번호 변경. 키가 발급됐다면 키를 재발급
   - 승인 전이라면 비밀번호만 바꾸면 돼요
4. 같은 비밀번호를 다른 곳에서도 썼다면 그곳도 변경 (메일, 포털 등)
5. 저장소에 비밀값이 올라가 있지 않은지 확인: 토큰, 키는 Secrets에만 있어야 해요. 코드나 문서에는 없어야 해요 (이 저장소는 공개 저장소라 코드는 누구나 볼 수 있어요)

## 2. 새 컴퓨터에서 다시 시작하기

설치할 건 없어요. 브라우저만 있으면 돼요.

1. 깨끗한 기기에서 GitHub에 로그인 (0번 보안 점검 먼저)
2. 저장소 `rode1024-cpu/job_01` 열기
3. 조건만 바꾸고 싶다면 `bot/config.yaml`을 열어 연필(수정) 아이콘 → 고치고 "Commit changes"
4. 봇이 도는지 확인: Actions 탭 → job-alert → 최근 실행이 초록색이면 정상
5. 바로 실행해보고 싶다면: Actions 탭 → job-alert → Run workflow → 브랜치를 `main`으로 선택 → 실행
6. 웹앱은 공개 주소로 열거나 `index.html`을 내려받아 브라우저로 열면 돼요

코드를 크게 고치고 싶을 때는 Claude Code(클라우드 세션)에 맡기는 방식을 써왔어요. 7번을 보세요.

## 3. 자주 바꾸는 설정 (`bot/config.yaml`)

설정 파일 하나만 고치면 되고, 파이썬 코드는 건드릴 필요가 없어요.

| 바꾸고 싶은 것 | 고칠 항목 | 현재 값 |
|---|---|---|
| 알림 받을 지역 | `regions` | 경기도 부천시, 서울 구로구, 서울 금천구, 서울 강서구, 서울 강남구 |
| 알림이 너무 많다 / 적다 | `notify_threshold` (올리면 적게 옴) | 55 |
| ★ 표시 기준 | `star_threshold` | 70 |
| 지역별 한 번에 보낼 최대 개수 | `max_alerts_per_run` | 5 |
| 검색 키워드 | `search_keywords` | 온라인MD, 채널MD, 이커머스MD, 브랜드MD, 이커머스 MD |
| 선호/제외 카테고리 | `good_categories`, `maybe_categories`, `exclude_categories` | 게임·IT·가전 등 / 패션·화장품·식품 등 |
| 계약직·인턴 감점 단어 | `contract_terms` | 계약직, 인턴, 파견, 수습 등 |
| 교육·훈련 광고 제외 단어 | `skip_terms` | 청년취업사관학교, 부트캠프 등 |
| 하루 요약 메시지 | `status_message` (`daily` / `quiet`) | daily |
| 잡코리아 검색 페이지 수 | `jobkorea_pages` | 3 |
| 상세 확인할 공고 수 | `jobkorea_max_detail` | 25 |

지역 쓰는 법: 시/구를 한 줄에 하나씩 쓰고, 구 이름이 겹치니 `서울 강서구`처럼 앞에 서울/경기/인천을 붙여요. `경기도 부천시`, `경기 부천시` 어느 쪽으로 써도 돼요.

## 4. 점수 규칙 (100점 만점)

| 항목 | 배점 | 요점 |
|---|---|---|
| 직무 | 15 | 제목에 온라인/채널/이커머스/브랜드 MD가 있으면 만점 |
| 경력 | 5 | 4~8년↑ 가점. 2~3년↑는 -10점, 경력무관은 -8점. 신입 전용, 3년 이하, 10년 이상은 탈락 |
| 카테고리 | 20 | 선호 2개 이상 만점. 제목·회사·직무분류에 제외 카테고리가 있으면 탈락 |
| 업무 | 15 | 채널 전략, 프로모션, 매출분석, 수요예측, 발주, 협상 등 |
| 지역 | 15 | 내가 정한 지역이면 만점 |
| 연봉 | 10 | 4,800 이상 만점. 회사내규/미기재는 감점 없이 중간 점수 |
| 조직·규모 | 10 | 상세페이지·촬영·CS 응대 등이 업무에 있으면 감점 |

- 공고에 없는 정보는 감점하지 않고 중간 점수(60%)를 줘요.
- 계약직·인턴·수습 등이 있으면 -10점이에요.
- 알림 기준은 55점 이상이고, 웹앱의 "지원 추천(70점)", "검토 후 지원(50점)" 기준과 비슷하게 맞춰 놨어요.

## 6. 지금까지 만든 과정 (요약)

1. 웹앱(MD 공고 체크) 제작: 공고를 붙여넣으면 조건별 판정과 면접 질문을 보여줌
2. 사람인·잡코리아 자동 알림봇을 `bot/`에 넣고, 점수 기준을 웹앱과 통일
3. 텔레그램 연결, 전송 실패 로그 추가, 전송 성공한 공고만 "본 공고"로 기록
4. 알림 지역을 설정 파일(`regions`)로 정하고 지역별로 묶어서 전송
5. 실행 시각을 하루 3번으로 줄이고, 정각을 피한 한가한 시각으로 변경 (GitHub가 정각 실행을 몇 시간씩 미룸)
6. 하루 한 번 결과 요약 메시지 추가 (알림이 0건이어도 봇이 도는지 알 수 있게)
7. 잡코리아 수집 개선: 검색 3페이지, 카드에서 먼저 거르기, 상세 페이지는 이름표로 읽기
8. 알림 품질 개선: 연차 낮은 공고 감점, 교육 광고 제외, 알림에 업종·고용형태 표시

## 7. 편집 방식 (이렇게 고쳐 왔어요)

### 7-1. Claude Code로 코드를 고칠 때 (주로 쓴 방식)
1. Claude Code(클라우드 세션)에 요청 → 작업 브랜치 `claude/beautiful-archimedes-ypc64m`에 수정과 커밋
2. Claude가 PR(합쳐달라는 신청서)을 만듦
3. 내가 GitHub에서 PR을 열어 "Merge pull request" → "Confirm merge"로 `main`에 합침
4. 합친 뒤 Actions에서 실행해 확인, 결과를 Claude에게 알려주고 다음 수정

### 7-2. 내가 직접 고칠 때
- 설정은 GitHub 웹에서 `bot/config.yaml`을 열어 수정하고 Commit (지역을 `경기도 부천시`로 바꾼 것도 이렇게 했어요)
- 이때 `main`에 바로 저장돼요. 다음 실행부터 적용돼요.

### 7-3. 고치기 전후에 하는 확인
- 점수 규칙: `bot` 폴더에서 `python test_scoring.py`, `python test_parsers.py`
- 웹앱 엔진: 저장소 루트에서 `node test.js`
- 실제 잡코리아에서 알림은 안 보내고 결과만 보기: Actions → `probe-jobkorea` → Run workflow
  - 이 도구는 `bot/probe/` 폴더에 결과 파일을 저장해요. 확인이 끝나면 그 폴더는 지워도 돼요.
- Claude가 일하는 환경은 잡코리아 접속이 막혀 있어서(네트워크 정책), 잡코리아 구조 확인은 GitHub 서버(Actions)로 우회하지 않고 점검 도구로 읽어 왔어요.

### 7-4. 지켜온 규칙
- 봇을 수동 실행할 때는 브랜치를 항상 `main`으로 고르기 (작업 브랜치에서 돌리면 `seen.json`이 그쪽에 저장돼서 합칠 때 충돌이 나요)
- 저장소의 기본 브랜치는 `main`이에요 (자동 실행은 기본 브랜치의 설정으로 돌아요)
- 비밀값은 코드나 문서에 쓰지 않고 Secrets에만 저장하기

## 8. 자주 겪은 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 알림이 한 건도 안 옴 | 봇이 멈춘 게 아니라 조건에서 다 걸러졌거나, 잡코리아 접속 실패 | 하루 요약 메시지의 숫자를 확인. 접속 실패 문구가 있으면 다음 실행을 기다리기 |
| 9시에 안 오고 몇 시간 늦게 옴 | GitHub 자동 실행이 정각에 몰려 밀림 | 이미 한가한 분(47분, 17분)으로 바꿨어요. 그래도 늦을 수 있어요 |
| 텔레그램 전송 실패 `Unauthorized` | 토큰이 틀림. 토큰에는 `bot`이 안 들어가요 (숫자부터 시작) | Secrets의 `TELEGRAM_TOKEN`을 다시 저장, 앞뒤 공백 확인 |
| 전송 실패 `chat not found` | 채팅 번호가 틀렸거나, 봇에게 `/start`를 안 보냄 | 봇에게 `/start` → `getUpdates`로 번호 다시 확인 |
| 지역을 써도 공고가 안 걸림 | 구 이름 겹침, 표기 차이 | `서울 강서구`처럼 앞에 서울/경기/인천을 붙이기 |
| PR 합칠 때 `seen.json` 충돌 | 작업 브랜치와 `main`이 각각 기록을 갱신함 | 두 쪽의 기록을 합치면 돼요 (키를 모두 남기면 됨) |
| 실행이 오래 멈춤 | 잡코리아 응답이 없음 | 실행 제한시간 10분이 있어서 자동 종료돼요 |

## 9. 남은 일과 보류 요청

1. 사람인 API 승인: 신청은 했고 승인 대기 중이에요. 승인되면 Secrets에 `SARAMIN_KEY`를 추가하면 사람인 공고도 같이 와요.
2. 보류한 요청 (아직 반영 안 됨): 이미 알림으로 보낸 공고도 다시 전송하되, "이전에 추천함"으로 표시하고, 이전에 추천한 공고는 알림 맨 마지막에 내용 없이 링크만 모아서 보내기. 지금은 한 번 보낸 공고는 다시 안 와요.
3. 부천, 구로, 금천 공고가 계속 안 오면: 검색어에 지역을 붙여서("부천 온라인MD" 등) 해당 지역 공고가 있는지 시험해 보기
4. 며칠 써보고 알림 기준(`notify_threshold`), 지역 목록, 키워드를 조정하기

## 11. 용어 풀이

- 저장소(repository): GitHub에 코드를 모아 두는 폴더
- 브랜치: 저장소의 작업 갈래. `main`이 정식 본선이에요
- PR(Pull Request): 작업 브랜치의 변경을 `main`에 합쳐달라는 신청서
- Actions: GitHub 서버에서 자동으로 프로그램을 돌려주는 기능 (봇이 여기서 돌아요)
- Secrets: 토큰, 키 같은 비밀값을 안전하게 저장하는 GitHub 설정 칸
- 카드: 잡코리아 검색 결과에서 공고 하나를 보여주는 한 칸
